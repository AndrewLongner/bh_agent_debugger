# Service + CLI Architecture (Step 1)

This document defines the target architecture and command surface for replacing `bh_agent_debugger.ps1` with a service + CLI model.

## Goals

- Deterministic routing when multiple `devenv` instances and multiple agent packages are running.
- Stable command execution with explicit targeting (`suffix`, `pid`, or `target id`).
- Script-compatible migration path from current PowerShell workflows.

## Components

- `agentd` (broker/service)
  - Long-running local process.
  - Discovers Visual Studio instances and maintains a live target table.
  - Routes commands to the correct package instance.
  - Centralizes retries, timeouts, logging, and health checks.

- `agentctl` (CLI)
  - User-facing command tool.
  - Sends requests to `agentd`.
  - Supports human-readable and JSON output.

- package endpoint (in each VS instance)
  - Receives commands scoped to that instance.
  - Talks to existing package/engine messaging path.

## Runtime Model

- One local `agentd` per machine/session.
- Zero or more active VS targets discovered by `agentd`.
- Every mutating command resolves to exactly one target.
- Ambiguous target resolution is a hard error.
- `agentctl` never talks to package endpoints directly.
- Only `agentd` talks to package endpoints; package can continue to talk to local/remote components as it does today.

## Target Identity

Each discovered target is represented by:

- `targetId` (stable short id generated by service)
- `pid` (`devenv` process id)
- `rootSuffix` (for example `Exp`, `ExpTarget`)
- `registryRoot`
- `solutionPath`
- `debugMode` (`design`, `run`, `break`, `unknown`)
- `endpoint` (service-internal transport address)

Selection precedence for CLI commands:

1. `--target-id`
2. `--pid`
3. `--suffix` (+ optional `--solution` to disambiguate)

## Command Surface (v1)

### Discovery and health

- `agentctl targets list [--json]`
- `agentctl targets show --target-id <id> [--json]`
- `agentctl doctor [--json]`

### Messaging and diagnostics

- `agentctl send --target-id <id> -- "status"`
- `agentctl send --suffix <name> -- "set trap symbol target_work"`
- `agentctl diag session --target-id <id> [--json]`

### Debug orchestration

- `agentctl start main --solution <path> --startup <path> --config <cfg> --platform <plat>`
- `agentctl start-debugging <solution-hint>`
- `agentctl stop main`
- `agentctl start exp --suffix <name> --solution <path> --startup <path> --config <cfg> --platform <plat> [--force-launch]`
- `agentctl stop exp --suffix <name> [--kill]`

### Workflow support

- `agentctl chain run --file <workflow.json>`

`chain run` is the queue replacement. It executes ordered steps and fails on first hard error unless configured otherwise.

## Service Responsibilities

- Discover and refresh target table.
- Validate target resolution for each request.
- Execute command with timeout/retry policy.
- Emit structured logs with request id and target id.
- Return consistent error codes for CLI and automation.

## Non-goals for Step 1

- Wire-level protocol details.
- Exact named pipe schema.
- Full implementation schedule.

Those are covered in later steps.

Protocol details are now documented in `SERVICE_CLI_PROTOCOL.md`.

## Migration Strategy

- Keep `bh_agent_debugger.ps1` during transition.
- Add wrapper mode in script to call `agentctl` equivalents.
- Deprecate direct pipe usage after feature parity.

## Implementation Status

- Implemented in bootstrap form:
  - broker transport (`agentd serve`)
  - CLI send/routing (`send`, `send-target`, `targets-list`)
  - core command wrappers (`status`, `list-solutions`, `diag-session`, `set-trap`, `read-regs`, `read-stack`)
  - orchestration wrappers (`start-main`, `stop-main`, `start-exp`, `stop-exp`) via native broker DTE calls
- Remaining details and cutover sequencing are tracked in `SERVICE_CLI_CUTOVER_PLAN.md`.
